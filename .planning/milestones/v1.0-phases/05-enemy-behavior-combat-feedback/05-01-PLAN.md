  <name>Task 2: Implement AI state machine, enemy firing with lead prediction, wire into render loop</name>
  <files>js/scene/combat.js, js/scene/weapons.js, index.html</files>
  <action>
This task implements the full enemy AI behavior loop and enemy weapon firing.

**In js/scene/combat.js:**

1. Add tuning constants near the top:
```javascript
const DETECT_RADIUS = 40;          // world units -- player detection range
const DETECT_RADIUS_SQ = DETECT_RADIUS * DETECT_RADIUS;
const ALERT_PAUSE = 0.5;           // seconds in alert state before transfer
const ATTACK_RANGE = 15;           // start attack pass within this distance
const FIRE_RANGE = 10;             // fire weapon within this distance
const DISENGAGE_DIST = 5;          // start disengage when this close
const REORBIT_DIST = 20;           // re-orbit when this far from player
const STATION_KEEP_ALT = 3.0;      // altitude above planet surface for station-keeping
const GUIDANCE_ACCEL = 3.0;        // mid-course correction acceleration for transfers
const ACCURACY_NOISE = 5.0;        // aim noise in world units (lower = more accurate)
```

2. Implement `updateEnemyAI(simDt, simTime, playerPos, playerVel, playerBody)` function with the state machine. For each alive enemy, first decay flash (`enemies.flash[i] = Math.max(0, enemies.flash[i] - simDt / 0.2)`), then switch on `enemies.aiState[i]`:

**AI_IDLE (station-keeping):**
- Get assigned body position via `getBodyPosition(enemies.assignBody[i])`
- Compute station angle: `planetAngle + enemies.stationPhase[i]` where `planetAngle = Math.atan2(bodyPos[0], bodyPos[2])`
- Set enemy position at `bodyPos + stationR * [sin(angle), 0, cos(angle)]` where `stationR = getBodyRadius(enemies.assignBody[i]) + STATION_KEEP_ALT`
- Note: `getBodyRadius` is a helper that returns the planet radius for the given index. If it doesn't exist, use a reasonable constant (e.g., 2.0 for most planets). Actually, use the `planetData` array's `radius` field -- expose via a simple helper or use inline lookup.
- Set velocity to match body orbital velocity via `getBodyVelocity(enemies.assignBody[i])`
- Set heading from velocity direction
- Check distance to playerPos: if `dx*dx + dz*dz < DETECT_RADIUS_SQ`, transition to AI_ALERT, reset aiTimer

**AI_ALERT (brief pause before transfer):**
- Increment aiTimer by simDt
- If `aiTimer >= ALERT_PAUSE`:
  - Determine target body (the body the player is nearest to, using playerBody parameter)
  - Store in `enemies.targetBody[i]`
  - Compute transfer: use vis-viva approach. Get current enemy radius from BH, get target body radius from BH. Compute transfer semi-major axis `a = (r1+r2)/2`, compute required velocity at r1 via vis-viva `v = sqrt(BH_GM * (2/r1 - 1/a))`. Current speed from enemy velocity. Apply prograde impulse of `dv = v_transfer - v_current` in prograde direction.
  - `BH_GM` should be the gravitational parameter used by `computeGravAccel`. Read from the existing codebase -- it's typically the mass constant. Use `4000` (the BH mass in the shader/physics, check nav.js for the exact value).
  - Transition to AI_TRANSFER, reset aiTimer, set hasFired=0

**AI_TRANSFER (physics-based flight toward player's body):**
- Apply gravity: `const [ax, az] = computeGravAccel(enemies.posX[i], enemies.posZ[i])`
- Mid-course guidance: compute vector to target body position, apply small correction acceleration (GUIDANCE_ACCEL) perpendicular to velocity toward the target
- Leapfrog integration: `velX += ax*simDt; velZ += az*simDt; posX += velX*simDt; posZ += velZ*simDt;`
- Update heading from velocity direction
- Check distance to playerPos: if within ATTACK_RANGE, transition to AI_ATTACK, reset aiTimer

**AI_ATTACK (approach and fire):**
- Continue physics (gravity + leapfrog integration, no guidance correction)
- Update heading toward player
- If NOT hasFired AND distance to player < FIRE_RANGE:
  - Call `enemyFireAt(i, playerPos, playerVel)` (defined in weapons.js, see below)
  - Set `enemies.hasFired[i] = 1`
  - Spawn muzzle flash: `spawnExplosion(enemies.posX[i], 0, enemies.posZ[i], 0.6)`
- If distance to player < DISENGAGE_DIST OR (hasFired AND aiTimer > 1.0):
  - Transition to AI_DISENGAGE, reset aiTimer

**AI_DISENGAGE (pull away):**
- Apply small retrograde impulse on entry (first frame only, when aiTimer is near 0): reduce speed by ~20% to raise apoapsis
- Continue physics (gravity + leapfrog)
- Update heading from velocity
- If distance to player > REORBIT_DIST OR aiTimer > 3.0:
  - Transition to AI_REORBIT, reset aiTimer

**AI_REORBIT (circularize and prepare for next pass):**
- Circularize: compute circular velocity at current radius, apply impulse to match
- Immediately transition to AI_ATTACK, reset aiTimer, set hasFired=0
- This creates the loop: attack -> disengage -> reorbit -> attack -> ...

Use pre-allocated scratch arrays (e.g., `const _scratch = [0,0,0];`) for intermediate vector calculations to avoid per-frame allocation.
