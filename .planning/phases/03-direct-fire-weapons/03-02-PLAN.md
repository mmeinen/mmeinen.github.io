  <action>
Add projectile rendering, kinetic tracer trails, trajectory preview with hit prediction, and GL buffer setup to make the weapons system fully visible.

**Part A: Add to weapons.js -- trail buffer and render data**

1. **Shared kinetic trail ring buffer:**
   - `TRAIL_MAX_POINTS = 512` -- shared across all kinetic rounds
   - `trailBuf = new Float32Array(TRAIL_MAX_POINTS * 3)` -- xyz positions
   - `trailAlpha = new Float32Array(TRAIL_MAX_POINTS)` -- per-point alpha (for fade)
   - `trailHead = 0, trailCount = 0`
   - Each frame, for each alive kinetic projectile, push its current position into the ring buffer at `trailHead`. Set alpha to 1.0. Increment trailHead modulo TRAIL_MAX_POINTS. Increment trailCount (capped at TRAIL_MAX_POINTS).
   - Each frame, decay all trail point alphas by `simDt * 4.0` (fade over ~0.25s). Remove points where alpha <= 0 by setting alpha to 0.
   - Add trail push logic inside `updateProjectiles()` -- after position update, before despawn checks.

2. **Trajectory preview computation:**
   - `PREVIEW_STEPS = 80` -- fewer than full TRAJ_STEPS for performance
   - `PREVIEW_SIM_DT = 0.5` for kinetic (covers ~40s of flight time)
   - `previewBuf = new Float32Array(PREVIEW_STEPS * 3)` -- xyz positions for preview dots
   - `previewCount = 0` -- actual number of preview points
   - `hitPredictionPoint = null` -- [x, 0, z] if trajectory intersects an enemy, else null
   - `hitPredictionIdx = -1` -- enemy index if hit predicted

   `computeWeaponPreview(simTime)`:
   - If `!combatMode || !aimDir` return (clear previewCount to 0).
   - If `selectedWeapon === 0` (KINETIC):
     - startPos = [flyPos[0], 0, flyPos[2]]
     - startVel = [flyVel[0] + aimDir[0]*KINETIC_SPEED, 0, flyVel[2] + aimDir[2]*KINETIC_SPEED]
     - Call `simulateTrajectory(startPos, startVel, simTime, PREVIEW_STEPS, PREVIEW_SIM_DT, previewBuf, null, 0, 0)`
     - Store returned step count in previewCount
     - Check each preview point for enemy intersection: compute r, call `getCollisionCandidates(r)`, check distance squared against HIT_RADIUS_KINETIC^2. On first hit, store hitPredictionPoint and hitPredictionIdx, break.
   - If `selectedWeapon === 1` (PLASMA):
     - Linear preview: for s = 0 to PREVIEW_STEPS-1, compute distance = s * (PLASMA_MAX_RANGE / PREVIEW_STEPS). Position = flyPos + aimDir * distance. Store in previewBuf. Set previewCount = PREVIEW_STEPS.
     - Same hit prediction check as kinetic.
   - Reset hitPredictionPoint = null before each computation.

3. **Projectile render data packing:**
   - `projRenderBuf = new Float32Array(MAX_PROJECTILES * 3)` -- packed positions for draw call

   `renderProjectiles(gl, trajPg, trajLocs, vpMat)`:
   - If projCount === 0 AND trailCount === 0, return early.
   - `gl.useProgram(trajPg)`
   - `gl.enable(gl.BLEND); gl.blendFunc(gl.SRC_ALPHA, gl.ONE)`  -- additive blend for bright tracers
   - `gl.uniformMatrix4fv(trajLocs.uMvp, false, vpMat)`

   **Kinetic round heads (white/yellow bright points):**
   - Pack all alive kinetic (type===0) projectile positions into projRenderBuf contiguously.
   - Count them as kCount.
   - If kCount > 0:
     - `gl.bindBuffer(gl.ARRAY_BUFFER, projGlBuf)` (GL buffer, created in index.html setup)
     - `gl.bufferSubData(gl.ARRAY_BUFFER, 0, projRenderBuf.subarray(0, kCount * 3))`
     - `gl.enableVertexAttribArray(trajLocs.aPos)`
     - `gl.vertexAttribPointer(trajLocs.aPos, 3, gl.FLOAT, false, 0, 0)`
     - `gl.uniform4f(trajLocs.uColor, 1.0, 0.94, 0.71, 1.0)` -- white/yellow (255,240,180)
     - `gl.uniform1f(trajLocs.uPtSize, 4.0)` -- slightly larger than trail
     - `gl.drawArrays(gl.POINTS, 0, kCount)`

   **Kinetic trails (faded white/yellow points):**
   - Pack trail positions where trailAlpha > 0 into projRenderBuf. Count as tCount.
   - If tCount > 0:
     - Upload and draw as GL_POINTS with `uColor = (1.0, 0.94, 0.71, 0.5)` (dimmer) and `uPtSize = 2.0` (smaller).
     - Note: trajFS uses uniform color, so per-point alpha fading is approximated by the uniform alpha. This is acceptable -- the trail is a stream of fading dots, not per-pixel perfect. Alternative: render in batches of alpha ranges. Keep it simple: single draw call with medium alpha.

   **Plasma bolt heads (cyan glow):**
   - Pack all alive plasma (type===1) projectile positions into projRenderBuf. Count as pCount.
   - For each plasma bolt, compute fade factor: `fade = proj.distTrav[i] < PLASMA_FADE_START ? 1.0 : 1.0 - (proj.distTrav[i] - PLASMA_FADE_START) / (PLASMA_MAX_RANGE - PLASMA_FADE_START)`. Clamp 0-1.
   - Render in two passes per the RESEARCH recommendation:
     - **Glow pass:** Large point (12.0 * fade px), cyan with low alpha: `uColor = (0.0, 0.86, 1.0, 0.3 * fade)`, `uPtSize = 12.0 * fade`.
     - **Core pass:** Smaller point (5.0 * fade px), white-hot: `uColor = (0.9, 0.95, 1.0, fade)`, `uPtSize = 5.0 * fade`.
   - Since trajFS uses uniform color (not per-vertex), and we may have multiple plasma bolts at different fade levels, render each plasma bolt individually if count is small (typically 1-2 active). With MAX_PROJECTILES=128 but plasma cooldown of 2.5s, there will rarely be more than 2-3 plasma bolts alive simultaneously. Per-bolt draw calls are acceptable here (not the performance concern that per-kinetic draws would be).

   - `gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA)` -- restore normal blend after rendering
   - `gl.disableVertexAttribArray(trajLocs.aPos)` at the end

   `renderWeaponPreview(gl, trajPg, trajLocs, vpMat)`:
   - If previewCount === 0 return.
   - `gl.useProgram(trajPg)`
   - `gl.enable(gl.BLEND); gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA)`
   - `gl.uniformMatrix4fv(trajLocs.uMvp, false, vpMat)`

   **Kinetic preview (white/yellow curved dots):**
   - If selectedWeapon === 0:
     - Upload previewBuf to projGlBuf
     - `uColor = (1.0, 0.94, 0.71, 0.4)` -- semi-transparent
     - `uPtSize = 2.5`
     - `gl.drawArrays(gl.POINTS, 0, previewCount)`

   **Plasma preview (cyan dots that shrink):**
   - If selectedWeapon === 1:
     - Upload previewBuf to projGlBuf
     - `uColor = (0.0, 0.86, 1.0, 0.35)` -- semi-transparent cyan
     - `uPtSize = 3.0` -- Note: uniform point size means all dots same size. For the "shrinking" effect, render in 2-3 segments: first third at 3.0, second third at 2.0, last third at 1.5. Use separate drawArrays calls with offset/count.

   **Hit prediction marker:**
   - If hitPredictionPoint is not null:
     - Upload hitPredictionPoint to projGlBuf (single point)
     - `uColor = (1.0, 0.3, 0.2, 0.9)` -- bright red/orange for danger
     - `uPtSize = 10.0` -- large, unmissable
     - `gl.drawArrays(gl.POINTS, 0, 1)`

   - `gl.disableVertexAttribArray(trajLocs.aPos)` at the end

**Part B: Add to index.html -- GL buffers and render calls**

1. **GL buffer creation (near existing trajectory buffer setup):**
   - Create `projGlBuf = gl.createBuffer()`. Allocate with `gl.bufferData(gl.ARRAY_BUFFER, MAX_PROJECTILES * 3 * 4, gl.DYNAMIC_DRAW)` -- pre-allocate for max projectiles.

2. **Render calls (in the flyMode render block, AFTER enemy rendering, BEFORE existing trajectory preview):**

   - Call `renderWeaponPreview(gl, trajPg, trajLocs, _vpMat)` -- draw preview dots
   - These calls go after the enemy instanced draw and before the existing orbit trajectory preview. The existing trajectory preview (orbit path) should be hidden when combatMode is true (weapon preview replaces it).

3. **Gate existing trajectory preview on combat mode:**

- Both visually distinct from enemy red (255,80,60) and player blue HUD (60,140,255).
- Trajectory preview: kinetic = curved white/yellow dots, plasma = straighter cyan dots shrinking toward range limit.
