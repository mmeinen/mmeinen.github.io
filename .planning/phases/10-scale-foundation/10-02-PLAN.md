<objective>
Implement Camera-Relative Rendering (CRR) and logarithmic depth buffer to eliminate float32 precision jitter and Z-fighting at km-scale distances, while keeping normal (non-nav) mode completely untouched.

Purpose: Without CRR, float32 precision at 113,000 km has ~8m resolution -- causing visible jitter on 500m enemies. Without log depth, the 1/z depth distribution creates Z-fighting across a 1:600,000 near/far ratio. These two changes make km-scale rendering viable.

Output: CRR applied to all nav/combat render paths, log depth in all 3D geometry fragment shaders, gated perspective matrix.
</objective>

<task type="auto">
  <name>Task 2: Add logarithmic depth buffer via EXT_frag_depth</name>
  <files>js/scene/shaders.js, index.html</files>
  <action>
    Add logarithmic depth buffer to all 3D geometry fragment shaders used in nav/combat mode. This prevents Z-fighting across the km-scale near/far ratio (1:600,000).

    **Changes:**

    1. **index.html (WebGL init, near gl.getContext):**
       - Acquire extension: `const extFragDepth = gl.getExtension('EXT_frag_depth');`
       - Store as a global or pass to shader compilation
       - If null: log a warning but continue (fallback: accept minor Z-fighting at extreme ranges, use tighter near=10.0 far=300000 if ext unavailable)

    2. **js/scene/shaders.js (enemy vertex/fragment shader):**
       - Add to the TOP of the enemy fragment shader: `#extension GL_EXT_frag_depth : enable`
       - Add to the END of the enemy fragment shader main():
         ```glsl
         #ifdef GL_EXT_frag_depth
           float logDepthFar = 600000.0;
           gl_FragDepthEXT = log2(max(1e-6, 1.0 + gl_FragCoord.w)) / log2(1.0 + logDepthFar);
         #endif
         ```
       - Note: `gl_FragCoord.w` = 1.0/clip_w, which gives the reciprocal of the camera-space depth. The log formula maps this to a logarithmic distribution.

    3. **js/scene/shaders.js (any other 3D geometry fragment shaders):**
       - Apply the same log depth addition to ALL fragment shaders used for 3D geometry in nav mode: ship shader, projectile shader, missile shader, explosion billboard shader, shield shader, breakup shader
       - Check which shaders are in shaders.js vs inline in index.html. Apply to ALL of them.
       - The `#ifdef GL_EXT_frag_depth` guard means shaders still compile if extension is unavailable

    4. **Do NOT touch:**
       - The ray march shader (fsSource in shaders.js / index.html) -- it renders a full-screen quad, depth is irrelevant
       - Any shader used only in non-nav mode

    **Performance note:** Log depth disables early-Z optimization (5-15% fragment shader overhead). This is acceptable for the project's entity count.

    **Fallback behavior:** If `extFragDepth` is null at runtime:
    - Use tighter perspective: near=10.0, far=300000.0
    - Accept minor Z-fighting at extreme ranges (>100,000 km)
    - Implement this fallback in the mat4Perspective call from Task 1 (already gated on flyMode)
