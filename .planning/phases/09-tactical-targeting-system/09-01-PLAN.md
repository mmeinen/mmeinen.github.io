**Per-frame marker update -- add in the render loop, in the HUD update section (after the enemy indicator update block, around line ~1090):**

When `tacticalMode && playerState.alive`:

1. Show tacMarkerContainer. Iterate all MAX_ENEMIES slots:
   - If `!enemies.alive[i]`: hide marker, continue.
   - Project enemy position to screen using the standard projection formula (same as used for indicators and lock reticles -- use the already-extracted `_camP`, `_camF`, `_camR`, `_camU` camera vectors and `mD`).
   - If `dp <= 0` (behind camera): hide marker, continue.
   - Compute `sx`, `sy` screen coordinates.
   - Determine on-screen: `sx >= 0 && sx <= baseWidth && sy >= 0 && sy <= baseHeight`.
   - If on-screen: position marker via `style.transform = 'translate(' + (sx - 20) + 'px,' + (sy - 20) + 'px)'`. Add class `on-screen`, set `pointerEvents = 'auto'`.
   - If off-screen: hide the marker (off-screen enemies are NOT shown as markers per user decision -- they are not selectable and the regular indicators are hidden in tactical mode, so off-screen enemies simply have no marker).
   - Show marker: `style.display = 'block'`.
   - Update type text: `querySelector('.tac-type').textContent = '[' + ARCHETYPE_ABBREVS[enemies.type[i]] + ']'`.
   - Update distance: compute distance from flyPos to enemy position (2D XZ distance), show as `Math.floor(dist) + 'u'`.
   - Set archetype color on the type text: use `ARCHETYPE_COLORS[enemies.type[i]]` to set the color style as rgba (multiply by 255 for CSS).

2. When `!tacticalMode`: set `tacMarkerContainer.style.display = 'none'` (quick exit, no per-marker iteration needed since container is hidden).

**IMPORTANT performance note:** Cache querySelector results. During pool creation (Task 1), store references to the inner spans on the element object itself:
```javascript
el._typeSpan = el.querySelector('.tac-type');
el._distSpan = el.querySelector('.tac-dist');
el._wpnSpan = el.querySelector('.tac-wpn');
el._ringDiv = el.querySelector('.tac-ring');
el._infoDiv = el.querySelector('.tac-info');
el._hpSpan = el.querySelector('.tac-hp');
```
Then use `tacMarkerEls[i]._typeSpan.textContent` etc. in the render loop to avoid querySelector per frame per enemy.

**GL Range Rings -- add in the render loop, in the GL drawing section, after the orbit ring drawing code, gated on `tacticalMode`:**

1. Define ring radii: `const RING_RADII = [30, 50, 70, 90];` (these correspond roughly to inner/mid/outer planet orbits and beyond). Use 4 rings for visual clarity without clutter.

2. When `tacticalMode`:
   - Use the existing `trajPg` shader program (already used for orbit ring and trajectory preview).
   - Set MVP uniform from `vpMat`.
   - Bind `projGlBuf` (or allocate a small buffer if projGlBuf is too small -- it should be fine since trajectory uses it for 512+ points).
   - For each radius in RING_RADII:
     - Fill a Float32Array with 64 vertices forming a circle on the XZ plane (y=0): `x = radius * cos(angle), y = 0, z = radius * sin(angle)`.
     - `bufferSubData` the vertices.
     - Set color uniform to faint blue: `gl.uniform4f(trajLocs.uColor, 0.235, 0.549, 1.0, 0.08)` (very faint).
     - Set point size: `gl.uniform1f(trajLocs.uPtSize, 1.0)`.
     - Draw as `gl.LINE_LOOP` with 64 vertices.
   - Reuse the same Float32Array across all rings (just refill per radius).

3. Use `gl.enable(gl.BLEND)` and `gl.blendFunc(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA)` before drawing rings. Restore blend state after if needed by subsequent draws.

**IMPORTANT:** The ring buffer fill and draw should be efficient. Pre-compute the sin/cos table once if possible (or compute inline -- 4 rings x 64 segments = 256 trig calls per frame is negligible).

**IMPORTANT:** Ensure the ring drawing happens AFTER the blackhole/planet rendering but in the correct GL state. Follow the same pattern as the existing orbit ring drawing code -- use the same shader, same buffer binding pattern, same attribute setup.
