  **index.html -- Render loop -- Missile body rendering:**
  In the depth-tested rendering section (after enemy rendering, before/alongside projectile rendering):

  For each alive missile, render a 3D box body using the shipPg shader program:
  - Reuse existing missilePosBuf, missileNrmBuf, missileIdxBuf (already created ~line 284-290)
  - Compute model matrix: translate to missile.posX/posZ[i], rotate by atan2(missile.fwdX[i], missile.fwdZ[i])
  - For nuclear missiles (type=1): scale up by 1.8x, use whiter color [0.95, 0.85, 0.75]
  - For regular missiles (type=0): use existing MISSILE_COLOR [0.85, 0.35, 0.15] at normal scale
  - Set u_thrustIntensity based on fuel: if fuel > 0, intensity = 1.0. If fuel <= 0, intensity = 0.0 (engine dark).
  - NOTE: With up to 18 missiles, this is 18 individual draw calls. This is acceptable because missile body geometry is tiny (box = 12 triangles) and the alternative (instanced missile bodies) would require a custom shader since shipPg doesn't support instancing. If performance is a concern, switch to instanced rendering in a future plan.

  **index.html -- Render loop -- Missile trail rendering:**
  Add a shared trail ring buffer for missiles (similar to weapons.js kinetic trail pattern):
  - Pre-allocate: `const missileTrailMaxPts = 1024; const missileTrailBuf = new Float32Array(missileTrailMaxPts * 3); const missileTrailAlpha = new Float32Array(missileTrailMaxPts);`
  - Each frame, for each alive missile with fuel > 0: push position into trail ring buffer with alpha = 1.0
  - For coast phase (fuel <= 0): push with alpha = 0.3 (dim trail, sputtering visual per user decision)

  - Single draw call for all trails (pack into one buffer, render once). If mixed trail types: render in two passes (one for regular color, one for nuke color), or use a single average color. Claude's discretion -- two passes is cleaner.
